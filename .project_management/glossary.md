# Glossary

The words the screens, toasts and docs use. One definition per term; the synonyms to avoid stand after it.

**Library**: every track TrackVault manages, in the music folder on the hub. Not: collection, catalogue.

**Track**: one audio file in the library with its tags. Not: song, file (when the tags are meant).

**Hub**: the one machine that owns the music and the database. Not: server.

**Device**: a computer paired with the hub that runs the agent. Not: client, machine (in the screens).

**Local copy**: the part of the library a device keeps on its own disk. Not: replica, mirror, sync folder.

**Inbox**: where new files wait before they join the library. Not: staging, incoming.

**Inbox item**: one file in the inbox. It is *waiting* when it is ready to approve or needs a look (a duplicate, a decision, a failure). Not: upload, import (an import is a playlist import).

**Auto-tag review**: the place where tag proposals from the lookup providers wait for an accept or a reject. Not: Review, proposals page.

**Rules**: the ordered tag rewrites the owner switches on and runs over the library or chosen tracks. Not: cleanup rules, auto-clean.

**Tags**: the owner's own labels (vibe, set position, venue) put on tracks. Not: custom tags, my tags (that is Rekordbox's word for its own).

**Genre**: one name from the taxonomy a track's genre is tidied to. **Alias**: another spelling of an artist, a label or a genre, with the name to use instead.

**Tidy spellings**: rewriting genres, artists and labels to their canonical spelling. Not: unify, normalise.

**Duplicates**: tracks that are the same recording, grouped, with the copy to keep. Not: dupes.

**Issues**: the problems the library has (a missing title, a low bitrate, a corrupt file), each opening the tracks it concerns.

**Organiser**: moves files into folders by a template.

**Soulseek**: the place that searches the Soulseek network and downloads a candidate. Not: Search.

**Candidate**: a file a Soulseek search offers, ranked best first.

**Download**: a candidate being fetched; the finished file goes to the inbox.

**Wishlist**: the tracks the library lacks and the owner wants; the hub searches for them. **Wishlist item**: one entry. Not: want, wanted track.

**Playlist**: an ordered list of tracks, a folder of playlists, or a smart playlist whose rule picks the tracks. **Set builder**: the place that suggests what plays next to build a set.

**Conflict**: a field changed in both Rekordbox and TrackVault since the last sync; the owner settles which side stays.

**Quarantine**: where removed tracks' files wait, restorable, before they are deleted for good.

**Batch**: the changes one action made together. **History**: the list of batches, each undoable. Not: changelog, log.

**Job**: a slow or bulk piece of work the hub runs in the background, with progress. Not: task.

**Backup**: a checked copy of the database. **Offsite**: backups and music sent to the owner's bucket. **Restore**: putting a backup back, with the hub stopped.

**Needs a look**: the state of something the hub cannot decide alone (an inbox item, a decision). Not: needs you, review.

**Banner**: the line at the top of the library saying what waits for the owner: inbox items, conflicts, a failed backup, a failed job. It is absent when nothing waits.
