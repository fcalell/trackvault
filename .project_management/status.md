## R1 progress

Built (hub, migration `0004_wise_cannonball`):
- **Change log and undo.** Every write goes through `server/lib/changes.ts` (`applyPatches`: 500-row chunks, prepared statements that set only the columns that changed, each field in `changes` under a batch id; `flushTagWrites` puts a batch's tag fields into the files from the log itself, so a job resumed after a stop finishes). `batches` lists them; the History place pages them (window) and a batch opens beside the list as a table of `change` cells with Undo batch. The `undo` job puts back only the fields still at the batch's value (conflicts are skipped and counted), tags the files and moves moved or quarantined files back; the undo is a batch of its own.
- **Bulk acts on the library selection** (`choose` over the window read, `selector(libraryQuery)` resolved by `libraryWhere`): Edit tags (a sheet with a live preview table of before and after for the first 40 tracks, then the `edit` job), Apply rules, Organise (with the saved template), Find duplicates of these, Quarantine.
- **Taxonomy.** `genres`, `genreAliases`, `artistAliases`, `labelAliases`; genres seeded from core's seed taxonomy on first start. Genres (taxonomy, unknown values with the closest names, map in a click), Aliases (spellings that differ by case or punctuation grouped for a merge, aliases), library-wide Unify (`unify` job, preview then apply).
- **Custom tags.** `tags`, `trackTags`; the Custom tags place, the record's Tags list, the Edit tags sheet (add or take off), and a Tag filter with counts in the library.
- **Cleanup rules.** `rules` (core `Rule` as JSON, core's built-ins seeded off); the screen lists, switches, adds and edits (one action per rule, a Form with fields per action kind) and previews on the library (`rules` job in preview mode stores rows in `previews`, read in windows) before the apply job.
- **Organiser.** Template field with presets, `organise` job: preview (moves, numbered collisions, unchanged; a table of path before and after) and apply (core's `orderMoves`, cycles through a temporary name, `files.path` updated with each move so the scanner reads nothing again, emptied folders removed). Undo through History.
- **Quarantine.** `files.state = quarantined`, files moved under `<libraryRoot>/.quarantine/<batch>/`, tracks hidden from the library (issue bit 2048, which the list leaves out only while some exist); Quarantine place with restore, delete now, restore all and empty; `purge` runs every 6 hours for files older than `settings.quarantineDays` (30).
- **Health.** Jobs `integrity` (ffmpeg decode) and `bitrate` (spectral cutoff, core quality), each degrading to a "needs ffmpeg" result; issue bits `corrupt` (512) and `fakeBitrate` (1024) with partial indexes; the Issues place lists every issue with its count and a link into the filtered library.
- **Dedupe.** Jobs `fingerprint` (fpcalc, stored in `fingerprints`), `dedupe` (core `groupDuplicates`, keeper and reason from `pickKeeper`, stored in `dupeGroups` and `dupeMembers`; a dismissed group stays dismissed by its member-set key) and `merge` (core `mergePlan`: tags filled, custom tags moved, other files quarantined, one batch). The Duplicates place shows groups as bands, keeper first with its reason, Merge on the band, "Not duplicates" and "Keep this one instead" on a row.

Measured at 50k tracks on the build sandbox (`scripts/bench-queries.ts`, `scripts/bench-jobs.ts`): window query plus total 1.6 to 6 ms unfiltered, search and facets unchanged (after moving the list onto stack's `paginateWindow`); jobs over the whole library: rules preview 1.8 s, unify preview 0.8 s, organise preview 3.8 s, dedupe (exact and fuzzy) 1.5 s, edit of every track 7 s in the database (50k changes logged) plus the file writes, undo of that batch similar.

Left: the hub on the homelab (R0 step 7); the acoustic tier is untested here (no `fpcalc` on the sandbox); Rekordbox-aware merge (cues, playlists) waits for R2 (`TrackFacts.cueCount` and `playlistIds` are empty).

## R2 progress

Built (hub, migration `0005_amusing_stryfe`; the agent and `packages/core/src/sync` were already there):
- **Playlists.** `playlists` (folders, manual, smart; sibling `position` real) and `playlistTracks` (`position` real, so a reorder writes one number: 2 ms on a 50k playlist). Every mutation is in `server/lib/playlists.ts` and logs into `changes` (entity `playlist`: `node`, `name`, `parentId`, `position`, `rule`, `member`) under a batch, so History lists it and the `undo` job reverses it (a 50k-member delete undoes in 9 s). Procedures: tree, get, window `tracks`, create, createSmart, updateSmart, preview, rename, move, remove, add (a few ids inline, a selection of the library or of another playlist is the `playlist-add` job), removeTracks, reorder, forTrack. Smart rules are core/smart `compileRule` over the tracks columns (`playCount`/`lastPlayedAt` are tracks columns the Rekordbox plays refresh; `durationSec` scales the ms column); the editor writes a flat list of lines (`shared/smart-lines.ts`). UI: sidebar Playlists group (flat, folder path in the name; manual playlists take dropped tracks), the Playlists place (tree, drop onto playlists and folders), the playlist place (library table over the playlist: drag rows out, reorder with the pointer or Alt+arrows, remove, edit rule), "Add to playlist" on the library selection.
- **Devices.** `auth({ devices: true })`; tables `devices`, `deviceFiles`, `rekordboxLinks` (tracks and playlists, per device), `conflicts`, `analysisBlobs`/`trackAnalysis`, `cues`/`cueSets`, `plays`, `uploads`, `importParts`, `trackTombstones`. The Devices place lists keys and machines (state, last seen, replica counts, Rekordbox write support, waiting export), pairs (key shown once with the agent's pair command), revokes, forgets, wakes; Conflicts opens beside it: a table to take Rekordbox's value or keep TrackVault's, for the ticked rows or all.
- **`/sync`.** `server/services/sync.ts` mounts the protocol: hello, manifest (a range scan of `tracks_version_idx` plus tombstones), files (Range, If-Range, hash headers, 409 `file-changed`), state, inbox check and resumable uploads (land in `<library>/Inbox/<device>/` and are scanned), Rekordbox import (idempotent by batch and part, base check, links, field and playlist 3-way merge, cues, plays, ANLZ wants), export stream with ack (cursor of change seq, library version, track and conflict position; playlists are skipped when the device already holds their content), ANLZ blobs, and the `devices` channel (snapshot, wake, conflict). File hashes now follow tag writes (`refreshFileHash` reads head and tail only) and bump the track's version, so a device that read the old file looks again.
- **Agent.** `HubRouter` is the hub's emitted `AppRouter` declaration (type-only); the agent depends on `hub` in the workspace so `pnpm check` builds the hub first.

Measured at 50k tracks (`scripts/bench-sync.ts`, `scripts/seed-bench.ts`): manifest pages of 1000, 4 to 6 ms each (50 pages, 0.25 s for the whole library; 1 ms at the head); a first import of a synthetic 50k-track install (50k links and tracks, 250 playlists with 50k memberships, 5k cue sets, 10k plays) 7.7 s in 50 parts (worst part 2 s), 1.9k field conflicts recorded; a 1000-field delta import 0.12 s; export from nothing 0.3 s for 2.3k changes, an idle export request 17 ms, a repeated import part 0 ms. A playlist window of 200 rows at offset 25000 in a 50k playlist 5 to 7 ms; adding 50k tracks to a playlist 1.6 s.

Verified end to end with the real agent against the real hub on the sandbox: pair, hello, manifest, download, folder upload (chunked, completed, scanned, then replicated back), live wake, and a Rekordbox import and export against a fake SQLCipher `master.db` (playlists and links merged, the new track exported).

Left: writing a real `master.db` cannot be checked here (no Rekordbox install; `rekordbox.allowedDbVersions` is empty until the spike in `packages/core/src/rekordbox/VERIFY.md`); smart playlists from Rekordbox are not imported (their rules are XML); sibling order of playlists is the hub's; undo of `colour` and `cues` changes is not implemented (the changes are logged); the sidebar shows playlists flat; pointer drag and reorder are untested in a browser (the screens test is static).
