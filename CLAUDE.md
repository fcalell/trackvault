# TrackVault

@apps/hub/.stack/guide.md

A self-hosted music library for DJs: one hub on a homelab owns the files and the database, a
browser (any PC or phone) is the UI, and an agent on each Rekordbox machine keeps a local replica.
Built on `@fcalell/stack`, consumed from the local checkout (`link:../stack/...`, never npm
versions); the guide above is stack's "how to build on stack", generated by `stack generate`
(run it once after a fresh clone, `pnpm --filter hub generate`). The dev shell is `flake.nix` through direnv.

Why and how: `.project_management/vision.md` (what it is for), `revamp-plan.md` (architecture,
performance budgets at 50k tracks, data model, phases, stack gaps, decisions), `status.md`
(where the work stands). Performance is the top priority; there is no backwards compatibility and
no test suite, the gate is `pnpm check`.

## Commands

```bash
pnpm dev                       # stack dev: hub on :8788, vite on :3000 (sign-in codes print in the hub's log)
pnpm check                     # type-check + Biome in every package; must pass
pnpm generate                  # stack generate (after a route, schema or service change outside dev)
pnpm build                     # the deployable bundle: apps/hub/dist (client/, server/server.mjs + workers, migrations)
pnpm --filter hub start        # run the built bundle: node dist/server/server.mjs (DB_FILE, AUTH_SECRET, APP_URL; PORT, HOST)
pnpm seed:bench                # 50k synthetic tracks into the dev database
pnpm --filter hub exec stack db generate   # the migration for a schema change (commit src/migrations)
```

## Rules

- Before editing the hub, open the page of stack's guide that the step needs (the index above);
  `src/app` follows `plugins/react-ui/guide/rules.md` strictly: roster components only.
- Library root, thresholds and other settings live in the `settings` row, not in env or config.
- Every bulk or slow operation is a job (`src/server/jobs/<kind>.ts`), safe to run twice.
- A hot write path uses the prepared statements in `src/server/lib/raw.ts`; the rest uses Drizzle
  through `@fcalell/plugin-db/orm`.
- The hub deploys as a bundle (`docs/deploy.md`): a worker thread is `new Worker(new URL("./x.ts", import.meta.url))` and a directory of
  modules is `loadModules(new URL("../jobs/", import.meta.url))`, both bundled by `stack build`; never read a file by a path relative to a module in server code.
- A stack gap is recorded, not patched: see `.project_management/revamp-plan.md` §10.
